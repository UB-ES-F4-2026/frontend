# US01.8: Tancar sessió

**COM** a usuari autenticat

**VULL** poder tancar sessió

**PER AIXÍ** finalitzar l'accés al meu compte en aquest navegador.

## 1. Especificació funcional

### 1.1. Contingut

- A l'escriptori, la capçalera mostra un control de menú de compte que inclou l’opció «Cerrar sesión». Aquesta història defineix aquesta acció sense limitar les opcions que altres històries puguin afegir al menú.
- Al mòbil, «Cerrar sesión» apareix com un element del menú de navegació.
- Les opcions «Iniciar sesión» i «Registrarse» es mostren quan no hi ha cap sessió iniciada.

### 1.2. Comportament

#### 1.2.1. Accés i navegació

- L'opció «Cerrar sesión» només està disponible per als usuaris autenticats, des de qualsevol pàgina que mostri la capçalera.
- A l'escriptori, el menú de compte està tancat inicialment i es pot obrir i tancar amb el seu control.
- El menú es tanca en prémer la tecla Esc o en interactuar fora del menú.
- Al mòbil, l'opció és accessible en obrir el menú de navegació, sense desplegar un segon menú de compte.
- Els controls es poden utilitzar amb teclat, tenen un nom accessible i mostren el focus. El control del menú comunica si està obert o tancat.
- En tancar el menú amb Esc, el focus torna al control que l'ha obert.

#### 1.2.2. Tancament de la sessió

- En seleccionar «Cerrar sesión», es finalitza la sessió del navegador actual sense demanar una confirmació addicional.
- El servidor elimina de la base de dades la sessió actual. El token associat deixa de permetre l’accés autenticat, encara que no hagi arribat a la seva data d’expiració.
- S'eliminen de l'estat de l'aplicació les dades del compte autenticat i el token d'accés.
- L'aplicació deixa d'utilitzar el token per fer sol·licituds autenticades.
- Es tanquen els menús oberts, es redirigeix l'usuari a la pàgina d'inici i es mostra el missatge «Has cerrado la sesión».
- La capçalera s'actualitza per mostrar les opcions «Iniciar sesión» i «Registrarse».
- Tornar enrere amb el navegador no restableix la sessió ni permet accedir a contingut que requereixi autenticació.
- L'usuari pot tornar a iniciar sessió amb les seves credencials.

#### 1.2.3. Expiració i gestió automàtica de sessions

- El sistema comprova periòdicament l’expiració de les sessions i elimina de la base de dades les sessions caducades.
- El servidor comprova que la sessió existeix i no ha caducat en cada sol·licitud autenticada; l’accés no depèn de quan s’executi la neteja periòdica.
- El frontend comprova periòdicament la vigència de la sessió mentre l’aplicació està oberta i també en reprendre-la després d’haver quedat en segon pla.
- Quan es detecta una sessió caducada o invàlida, es neteja l’estat autenticat, es redirigeix a l’inici de sessió i es mostra «Tu sesión ha caducado. Vuelve a iniciar sesión».
- Aquestes comprovacions són automàtiques i no requereixen cap acció de l’usuari.

#### 1.2.4. Errors i consistència de l'estat

- Si falla la comunicació amb el servidor, es neteja igualment la sessió local i es mostra «Se ha cerrado la sesión en este navegador, pero no se ha podido confirmar el cierre en el servidor». No es presenta el tancament al servidor com a completat.
- Una fallada de xarxa durant la comprovació periòdica no es tracta com una confirmació que la sessió ha caducat; la comprovació es reintenta quan es recupera la connexió.
- Repetir l'acció no provoca errors ni restableix les dades del compte.
- Una resposta pendent d'una sol·licitud anterior no pot restaurar la sessió després d'haver-la tancat.

## 2. Requisits tècnics

- El frontend centralitza el tancament de sessió en l'estat d'autenticació compartit, reutilitzant l'acció de tancament de sessió existent.
- S'eliminen el compte actiu, el token i les dades temporals associades a l'usuari que no hagin de quedar accessibles després del tancament.
- La navegació i la visibilitat dels controls reaccionen al canvi de l'estat d'autenticació.
- La redirecció utilitza React Router i substitueix l'entrada actual de l'historial.
- El frontend sol·licita al backend el tancament de la sessió actual abans d’eliminar el token local, i garanteix la neteja local encara que la sol·licitud falli.
- El backend identifica i elimina la sessió actual de la base de dades. Repetir el tancament d’una sessió ja eliminada no provoca errors.
- El backend rebutja els tokens associats a sessions eliminades o caducades en qualsevol operació protegida.
- Un procés periòdic del backend elimina les sessions caducades. Els intervals de neteja i de comprovació del frontend són configurables; no modifiquen la data d’expiració ni prolonguen la sessió.
- Els contractes d’API per tancar i comprovar la sessió s’han de definir amb el backend. L’acció local existent s’ha d’ampliar per cobrir aquests requisits.
- Els textos visibles de la interfície es mostren en castellà, d’acord amb `AGENTS.md`.
- Els components de menú preserven la navegació per teclat, la gestió del focus i la comunicació accessible del seu estat.

## 3. Abast i exclusions

Queden fora de l'abast d'aquesta User Story:

- Tancament de sessions en altres navegadors o dispositius.
- Consulta o gestió manual de sessions actives per part de l’usuari.
- Renovació automàtica de sessions i definició d’un termini addicional de tancament per inactivitat.
- Edició del perfil, configuració del compte i altres opcions del menú de compte.
- Eliminació del compte o modificació de les credencials.

## 5. Criteris d'acceptació

- **CA01.** Un usuari autenticat pot desplegar el menú de compte a l'escriptori i hi troba l'opció «Cerrar sesión».
- **CA02.** Al mòbil, un usuari autenticat troba «Cerrar sesión» com un element del menú de navegació, sense un segon menú desplegable.
- **CA03.** Els menús es poden utilitzar amb teclat; Esc tanca el menú de compte i retorna el focus al seu control, i la interacció fora del menú també el tanca.
- **CA04.** Seleccionar «Cerrar sesión» elimina la sessió actual de la base de dades i neteja el compte actiu i el token del frontend sense confirmació addicional. El servidor rebutja qualsevol ús posterior del token associat.
- **CA05.** Després del tancament, es mostra la pàgina d'inici amb el missatge «Has cerrado la sesión», els menús tancats i les opcions «Iniciar sesión» i «Registrarse».
- **CA06.** Un visitant no autenticat no veu l'opció «Cerrar sesión».
- **CA07.** Tornar enrere no restaura la sessió ni dona accés a contingut que requereixi autenticació, i les sol·licituds posteriors no utilitzen el token eliminat.
- **CA08.** Repetir el tancament o rebre una resposta pendent anterior no restaura la sessió ni provoca errors.
- **CA09.** Després de tancar sessió, l'usuari pot tornar a autenticar-se amb les seves credencials.
- **CA10.** El servidor rebutja les sessions caducades en cada sol·licitud autenticada, encara que el procés periòdic de neteja no les hagi eliminat.
- **CA11.** El procés periòdic elimina les sessions caducades de la base de dades i conserva les sessions vigents.
- **CA12.** Les comprovacions periòdiques del frontend i la comprovació en reprendre l’aplicació detecten les sessions caducades o invàlides, netegen l’estat autenticat i mostren l’inici de sessió amb el missatge d’expiració.
- **CA13.** Si falla la sol·licitud de tancament, es neteja l’estat local i s’informa que no s’ha pogut confirmar el tancament al servidor. Una fallada de xarxa durant una comprovació de vigència no es comunica com una expiració confirmada.
